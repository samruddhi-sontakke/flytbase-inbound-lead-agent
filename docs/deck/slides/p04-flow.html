Inbound Lead Desk · 4 / 15

[2:10 – 2:50] This is one tick of the agent. First it sweeps every unread email. Python scores each one for contact-form markers, and the agent decides whether it's a lead and writes down why. Then the stages run in dependency order. Stage 1 first. Research and case-study matching both need only Stage 1, so they run in parallel. The fact-checker runs on the research. Emails and partner identification run next, then the handoff. I did this on purpose: making every stage wait for the one before would only slow it down. Every stage saves through Python, which validates it, computes scores, checks it against the PDF, and stores it in MongoDB and in a run folder. There's a lock so only one lead runs at a time, and every subagent call is written to a trace.
